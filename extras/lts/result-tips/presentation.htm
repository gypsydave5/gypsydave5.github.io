Four? Result Tips

tip one

Result is never an argument

Looks something like this

val result: Result<Int, Error> = 
  parse(request)

val thingIWant = bizz(result)

// etc..

Yeuch

fun bizz(r: Result<Int, Error> {
  if (r is Failure) {
    return r
  }
  val actual = r.value
  
  // do BUSINESS
}

Prefer

parse(request)
  .flatMap { n -> bizz(n) }

fun parse(r: Req): Result<Int, Err> //...

fun bizz(n: Int): Result<More, Err> //...

tip two

use map and flatMap right

They both

Pass the Success value through a function

(Value) -> ???

flatMap is for

functions that do return a Result

(Value) -> Result<AnotherValue, Err>

fun parse(r: Request): Result<Int, Err> 

fun bizz(n: Int): Result<MoreStuff, Err>

val x: Result<MoreStuff, Err> = 
  parse(request)
    .flatMap { n -> bizz(n) }

map is for

functions that don't return a Result

(Value) -> AnotherValue

fun parse(r: Request): Result<Int, Err> 

fun toString(n: Int): String

val x: Result<String, Err> = 
  parse(request)
    .map { n -> toString(n) }

tip three

Only Operations That Can Fail Should Return A Result

flatMap addiction

parse(request)
  .flatMap { doAThing(it) }
  .flatMap { doAnotherThing(it) }
  .flatMap { moreStuffs(it) }
  .flatMap { oooohMapMe(it) }
  .flatMap { addOne(it) }
  .flatMap { flatMapThirst(it) }
  .flatMap(::lookMaAReference)
  //.. etc

bad addOne

fun addOne(n: Int): Result<Int, Err> =
  Success(n + 1)

"But what's the harm?"

meaning is important

good addOne

fun addOne(n: Int): Int =  n + 1

parse(request)
  .flatMap { doAThing(it) }
  .flatMap { doAnotherThing(it) }
  .map { addOne(it) }
  .flatMap { flatMapThirst(it) }
  //.. etc

map when things can't go wrong

flatMap when things can go wrong

tip four

Pragmatism

One single expression

submissionRepository
  .getSubmission(submissionId)
  .flatMap { sub ->
    jRepo.getJournal(sub.journalId)
       .map { journal ->
              sub to journal
            }
  }

Better (there is no Best)

val sub = submissionRepository
  .getSubmission(submissionId)
  .onFailure { return it }

val journal = jRepo
  .getJournal(sub.jFlowId)
  .onFailure { return it }

return Success(sub to journal)

Or Find Your Own Way

Just don't do this

submissionRepository
  .getSubmission(submissionId)
  .flatMap { sub ->
    jRepo.getJournal(sub.journalId)
       .map { journal ->
              sub to journal
            }
  }

Summary

  1. Don't use Result as an argument
  2. map things that can't fail
  3. flatMap things that can fail
  4. Don't return Result if you can't fail
  5. early return your Failures when collecting Results
